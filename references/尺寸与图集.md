# 尺寸、命名与图集

尺寸不是只有一个宽高。游戏素材还涉及单帧画布、多倍图、精灵单元格、留白、九宫格边距和平铺。全部由 `project.json` + `assets.yaml` 里的 `size` 控制，脚本负责算出最终矩阵。

## 预设表

文件：`library/presets/sizes.json`（每个工程里有一份 `presets/sizes.json` 副本，可改）。

| 预设 | 单帧尺寸 | 倍数 | padding | 透明 | 其它 |
|---|---|---|---|---|---|
| `icon` | 256×256 | 1x,2x | 8 | 是 | trim，center |
| `character` | 512×512 | 1x,2x | 8 | 是 | trim，bottom-center |
| `sprite` | cell 64，4 列 | 1x | 0 | 是 | bottom-center，不做 trim |
| `background` | 1920×1080 | 1x | 0 | 否 | cover 填充，不抠底 |
| `tile` | 64×64 | 1x,2x | 0 | 是（可带透明细节） | seamless，不抠底 |
| `ui` | 512×128 | 1x,2x | 0 | 是 | nineSlice 32 |
| `vfx` | cell 128，8 列 | 1x | 4 | 是 | center |

## 覆盖优先级

从低到高：

1. 类型预设（`presets/sizes.json` 里的同类型项）
2. 素材显式 `size.preset` 指定的预设
3. `project.json` 的 `sizes.<type>` 覆盖
4. `assets.yaml` 里该素材 `size` 的内联字段

例如：

```json
// project.json
{ "sizes": { "icon": { "width": 128, "scales": [1, 4] } } }
```

```yaml
# assets.yaml
- id: potion_red
  type: icon
  size: { preset: icon, width: 64, height: 64, scales: [1] }
```

最终：64×64，1x（素材内联最高优先级）。

## `size` 字段说明

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `width` / `height` | int | 预设 | 单帧画布尺寸（非 cell 模式） |
| `cell` | int | - | 精灵单元格边长；设置后 `width = cell × columns`，`height = cell × rows` |
| `columns` | int | 1 或帧数 | 精灵表列数 |
| `rows` | int | 自动 | 由帧数和列数算出，只读 |
| `scales` | int[] | `[1]` | 导出倍数，如 `[1,2,4]` |
| `padding` | int | 0 | 主体到画布边缘的安全边距 |
| `trim` | bool | true | 是否按 alpha 包围盒裁切后再补边 |
| `anchor` | str | center | `center` / `bottom-center` / `top-center` |
| `transparent` | bool | true | 是否需要透明底；false 时用 cover 填满画布 |
| `removeBg` | bool | 对象类 true | 无 alpha 时是否按纯色 key 去底；背景/tile 默认 false |
| `seamless` | bool | false | 是否做平铺接缝检查 |
| `nineSlice` | object | - | `{left,right,top,bottom}`，UI 九宫格边距 |
| `gap` | int | 0 | 精灵表帧间距 |
| `pixel` | bool | 由 `style.pixelGrid` 决定 | 是否用最近邻缩放 |

## 命名规则

输出文件名：`<type>_<id>[_<frame>]@<scale>x.png`

- `icon_potion_red@1x.png`
- `character_knight_walk@2x.png`
- `tile_grass@1x.png`

原始图路径：`raw/<type>/<id>/<frame>.png`；无帧素材：`raw/<type>/<id>/<id>.png`。

`id` 用小写蛇形，且必须唯一。它会成为文件名、manifest 键、图集键，改 id 等于改资源引用。

## 多倍图

- `scales: [1,2]` 会输出 `@1x` 和 `@2x` 两张，尺寸精确为单帧尺寸 × 倍数。
- 像素风和扁平风优先整数倍（1x/2x/4x），不要 1.5x。
- 原始图建议按最大倍数生成（`render.py` 默认这样做），后处理再缩小，避免放大糊。
- 引擎里通常只导入 1x，或按平台选择；不要同时导入多套导致资源重复。

## 精灵表公式

- 列数 `columns`：默认取 `max(1, 帧数)`；`sprite`/`vfx` 预设里显式给了列数。
- 行数 `rows = ceil(帧数 / columns)`。
- 单帧尺寸 = `cell × cell`（cell 模式）或 `width × height`（普通模式）。
- 图集尺寸：
  - 宽 = `columns × cell_w + gap × (columns − 1)`
  - 高 = `rows × cell_h + gap × (rows − 1)`
- 帧顺序 = `assets.yaml` 里 `frames` 的顺序，从左到右、从上到下。

例：6 帧、4 列、cell 64 → 2 行；图集 256×128；帧 0~3 在第一行，帧 4~5 在第二行前两格。

## atlas JSON 格式

`out/atlas/<id>.json`：

```json
{
  "cell": [64, 64],
  "columns": 4,
  "rows": 2,
  "gap": 0,
  "image_size": [256, 128],
  "frames": [
    {"index": 0, "name": "idle", "x": 0, "y": 0, "w": 64, "h": 64},
    {"index": 1, "name": "walk", "x": 64, "y": 0, "w": 64, "h": 64}
  ],
  "id": "knight",
  "name": "骑士",
  "type": "character",
  "frame_names": ["idle", "walk"],
  "source_frame_size": [64, 64]
}
```

`frames` 数组是逐帧坐标，`name` 与 `assets.yaml` 的帧名一致；`frame_names` 是按顺序的帧名快捷列表。引擎导入时按 `x/y/w/h` 切图，或直接按 `index` 顺序。

## 九宫格（UI）

`nineSlice` 表示四边不拉伸的厚度：

```json
"nineSlice": { "left": 32, "right": 32, "top": 32, "bottom": 32 }
```

约束：`left + right < width`，`top + bottom < height`，否则 `check_assets.py` 报 ERROR。

设计时四角细节放在边距内，中间区域可平铺；不要把圆角或描边画到中间。

## 平铺（tile）

- `seamless: true` 时，`check_assets.py` 比较左右边、上下边的平均色差，阈值 0.08。
- 平铺素材不要有明显中心构图、方向性阴影、四边不一致的光照。
- 透明 tile 允许边缘透明，但主体纹理要铺满，不透明像素占比 ≥ 30%。

## 常见尺寸错误

| 现象 | 原因 | 修法 |
|---|---|---|
| 进引擎被拉扁 | 原始图宽高比与目标画布不一致 | 按目标宽高比重画，或调 `anchor`/`transparent` 用 cover |
| 角色脚底不齐 | 每帧主体高度不同、anchor 不是 bottom-center | 用 `bottom-center`，或统一脚底坐标 |
| 图标大小不一 | 主体在画布里的占比不同 | 统一 `padding`，检查 `fill_ratio` |
| 精灵表帧错位 | `columns` 与帧数不匹配 | 重新算 `rows = ceil(frames/columns)` |
| 4K 图集内存爆 | 单帧过大、帧数过多 | 降低 cell 或拆成多个动作图集 |
| 2x 图糊 | 原始图只有 1x 大小，放大生成 | 按最大倍数渲染/生图 |
