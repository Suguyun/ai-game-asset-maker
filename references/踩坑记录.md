# 踩坑记录

动手前扫一遍。遇到怪问题先查这里，再改脚本。

## 1. tile / 背景被当成纯色背景抠空

**现象**：草地 tile 导出后只剩中间一个小点，周围全透明。
**原因**：`removeBg` 对 tile/background 也执行了纯色 key，整块纹理被判定为背景。
**修法**：`process.py` 已默认对 `background` / `tile` 关闭去底；自定义类型时显式写 `removeBg: false`。校验里的「内容几乎全透明」会兜底报 ERROR。

## 2. 透明底变成黑底或白边

**原因**：
- 生图工具不支持透明，给了一张纯色/场景背景。
- 去底容差不够，或主体边缘与背景色混合。
- 导出时被转成 JPG（JPG 不支持 alpha）。

**修法**：
- prompt 里明确 `transparent background, no backdrop`。
- 让生图工具用纯绿 `#00FF00` 或纯白背景，再跑 `remove_solid_bg`。
- 输出始终用 PNG；不要用 JPG 作为交付格式。
- 白边严重时重生成，或手工收缩 1px alpha。

## 3. 像素图被插值糊掉

**原因**：缩放用了 Lanczos；或原图尺寸不是目标整数倍；或 SVG 里有半像素坐标。
**修法**：
- `style.pixelGrid > 0`，`process.py` 自动用最近邻。
- 原始图按整数倍生成（32 → 128/256）。
- SVG 所有坐标用整数；加 `shape-rendering="crispEdges"`。
- HTML Canvas 设 `ctx.imageSmoothingEnabled = false`。
- 引擎导入时也选 Nearest，否则前功尽弃。

## 4. 精灵表帧错位 / 坐标对不上

**原因**：
- `columns` 与帧数不匹配，行数算错。
- 帧图尺寸不一致，图集单元格取最大值，导致部分帧偏移。
- 改了帧数但没重跑 `process.py`。

**修法**：
- 帧数变化后必须重跑 `process.py`，图集会重新拼。
- 所有帧先统一到同一 `cell` 尺寸。
- `check_assets.py` 会校验图集尺寸、帧数、单元格；不要跳过。

## 5. 同一角色各帧不像同一个人

**原因**：
- 每帧独立生成，prompt 只写「同上」。
- 没有身份锚点，服装、发型、配色每帧漂移。
- 比例/身高没有写死。

**修法**：
- 先做 idle 帧作为锚点，用户确认后再做其它帧。
- 有参考图能力就把 idle 当参考图；没有就把服装、发型、配色、身高、头身比逐条写进每帧 prompt。
- 后处理统一画布和脚底基线，但身份一致性仍需人眼审。

## 6. AI 图带文字、水印、签名

**原因**：生图模型习惯性加标题/水印/边框。
**修法**：
- 负向词固定加 `text, watermark, signature, logo, border, frame, UI`。
- 生成后联系表审图，发现就重生成。
- 不要用「裁掉」应付：裁切会破坏构图。

## 7. tile 接缝明显

**原因**：
- 四边光照不一致；中间有强焦点；边缘有方向性阴影。
- 生图模型不理解「无缝」。
- 透明边缘有半透明杂色。

**修法**：
- prompt 写 `seamless tileable texture, edges match, uniform lighting, no directional shadow`。
- `check_assets.py` 接缝阈值 0.08；超标先重生成。
- 仍不行用 offset-seam 修补（见 `后处理.md`）。
- 3×3 平铺预览必须人眼看一次。

## 8. UI 九宫格把角切坏

**原因**：
- `nineSlice` 边距太大，超过画布一半。
- 角部细节画到了可拉伸区域。
- 面板尺寸改小后没改边距。

**修法**：
- `left+right < width`、`top+bottom < height`，`check_assets.py` 会报 ERROR。
- 四角细节放在边距内；中间区域设计成可平铺。
- 面板尺寸变化时同步改 `nineSlice`。

## 9. 色板漂移 / 颜色数量暴涨

**原因**：
- 生图模型每次重新选色。
- code-draw 里手写了色板外的颜色。
- 缩放用了 Lanczos，产生过渡色。

**修法**：
- `paletteLock: true`，后处理量化到色板。
- code-draw 颜色从 `style.json` 抄，不另造。
- 像素风用最近邻缩放。
- `check_assets.py` 的主色距离和颜色数 WARN 是预警信号。

## 10. 成品尺寸被拉伸

**原因**：
- 原始图宽高比与目标画布不一致，又被强行 resize。
- `transparent: false` 的背景用了 contain，出现留白/拉伸。
- 多倍导出时先放大再裁切，顺序错。

**修法**：
- 原始图按目标宽高比生成。
- 透明素材 contain，背景 cover。
- 先统一到 1x，再按倍数缩放。
- `check_assets.py` 的尺寸 ERROR 必须清零。

## 11. 缺帧但流程继续跑

**原因**：`raw/` 里只放了一部分帧，`process.py` 逐个读，缺的会直接报错，但如果用户漏看了 stderr，会以为成功。
**修法**：
- 生成后先跑 `python3 scripts/plan.py --check-raw`，缺图逐项列出并退出码 1。
- 看 `out/process_report.json` 的 `errors`。
- 不要用「先导出已有的」应付。

## 12. 路径含空格 / 中文导致命令失败

**原因**：某些工具对空格和中文路径处理不好。
**修法**：
- 所有命令给路径加引号。
- 交付目录可以用中文，但 `codegen/src/` 下的文件名保持小写蛇形 ASCII。
- 不要用 `#`、`?`、`&` 作为文件名。

## 13. SVG 渲染依赖外部字体/图片

**原因**：SVG 里用了系统字体或外链图片，换机器渲染结果不同。
**修法**：
- SVG 只用形状和路径，不使用外部字体/图片。
- 需要文字时转成路径，或改用 UI 素材 + 引擎文字。
- `render.py` 用 ImageMagick，不保证所有 CSS filter；复杂效果拆成多层 SVG。

## 14. Playwright 截图背景不透明

**原因**：HTML body 有默认白底，或忘了 `omit_background=True`。
**修法**：
- CSS：`html, body { background: transparent; margin: 0; }`。
- `render.py` 已使用 `omit_background=True`。
- 截图前等待字体/绘制完成（脚本已加 120ms，复杂页面可在 HTML 里用 `document.fonts.ready`）。

## 15. 大图集吃内存 / 渲染失败

**原因**：单帧 512×512、几十帧，2x 图集可达几十 MB。
**修法**：
- 精灵表用 1x（`scales: [1]`），单帧图再按需导出 2x。
- 大动作拆成多个图集（按动作分 id）。
- 背景不要放进图集。

## 16. 先放大后量化，颜色变多

**原因**：量化只作用于 1x，放大时插值产生新颜色。
**修法**：
- `process.py` 的顺序是「统一画布 → 量化 → 多倍导出」。
- 像素风放大用最近邻，不会产生新颜色。
- 非像素风不要开 `paletteLock` 后再放大到很大倍数。

## 17. YAML 缩进 / 中文冒号

**原因**：`assets.yaml` 缩进错、用中文冒号、id 里带空格或大写。
**修法**：
- 用两个空格缩进，不要 Tab。
- 只使用英文冒号 `:`。
- `id` 用小写蛇形，唯一。
- 保存后跑 `python3 scripts/plan.py`，格式错误会直接报出来。

## 18. export 覆盖了用户的游戏工程

**原因**：直接 `--copy-to` 到用户工程，没有确认。
**修法**：
- 先导出到交付目录，让用户确认。
- 同步前备份用户原素材。
- 只覆盖同名文件，不删除用户其它文件；`export.py` 使用 `dirs_exist_ok=True` 合并复制。
