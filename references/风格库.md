# 风格库与 Style Card

这是**菜单，不是默认值**。每个游戏都要根据题材、视角、受众重新组合，并由用户看过样图后拍板。可以混搭，也可以自创菜单外的方向。

`style.json` 是项目风格的唯一真相：所有生图 prompt、代码绘制、后处理调色、校验都以它为准。**改风格只改这一个文件**。

## 内置方向

| 文件 | 一句话 | 适合 | 像素网格 | 色板锁定 |
|---|---|---|---|---|
| `像素冒险.json` | 16-bit 复古像素，硬边、有限色板 | 地牢、平台跳跃、Roguelike | 16 | 是 |
| `Q版卡通.json` | 大头小身、粗描边、糖果色 | 休闲、模拟经营、儿童向 | 0 | 否 |
| `暗黑奇幻.json` | 厚涂写实、冷光、烬色点缀 | 魂类、暗黑 RPG、卡牌 | 0 | 否 |
| `赛博霓虹.json` | 深蓝底、青/品红边缘光、发光条 | 科幻、赛博朋克、射击 | 0 | 否 |
| `手绘水彩.json` | 纸张颗粒、晕染边缘、柔和自然色 | 叙事、解谜、治愈 | 0 | 否 |
| `扁平矢量.json` | 纯色块、几何、无渐变 | 超休闲、UI、移动端 | 0 | 是 |
| `写实厚涂.json` | 厚笔触、电影三点光、材质细节 | AAA 概念图、写实角色 | 0 | 否 |

## 各方向要点

### 像素冒险
- 视觉：整数像素、1px 深色描边、2~3 阶明暗、有限色板。
- 生成：prompt 里强调 `16-bit pixel art`、`integer pixels`、`no anti-aliasing`；尺寸用 16/32/64 的整数倍。
- code-draw：SVG 全部用整数坐标的 `rect`/`path`，加 `shape-rendering="crispEdges"`；颜色只取色板。
- 常见错误：缩放用了 Lanczos、SVG 里有半像素坐标、渐变、模糊阴影。

### Q版卡通
- 视觉：大头小身、3~4px 圆角描边、糖果色、柔和赛璐璐阴影、贴纸感。
- 生成：`chibi`、`big head small body`、`thick clean outline`、`candy colors`。
- code-draw：用圆角矩形和大圆做身体，描边独立一层，保持粗细一致。
- 常见错误：比例忽大忽小、描边粗细不一、光源方向乱。

### 暗黑奇幻
- 视觉：低饱和、冷主光 + 暖烬色反弹、金属/皮革/石材质感、深阴影。
- 生成：`dark fantasy`、`painterly realism`、`dramatic rim light`、`weathered metal`。
- code-draw：不适合逐笔厚涂，建议只用它做 UI 边框、图标底框等平面元素；角色/场景走生图。
- 常见错误：颜色过艳、塑料感、对称构图。

### 赛博霓虹
- 视觉：近黑夜空、青色与品红边缘光、发光条、硬表面、全息面板。
- 生成：`cyberpunk`、`neon rim light`、`dark navy background`、`emissive accents`。
- code-draw：很适合图标、UI、发光线条；用纯色 + 外发光（SVG filter 或叠层）。
- 常见错误：暖日光、自然有机形状、低对比。

### 手绘水彩
- 视觉：纸张颗粒、颜料晕染、宽松墨线、自然低饱和色。
- 生成：`hand-painted watercolor`、`visible paper grain`、`soft bleeding edges`。
- code-draw：用 SVG 路径 + 轻微抖动 + 半透明叠色模拟；不要在像素网格上画。
- 常见错误：硬矢量边、霓虹色、完美对称。

### 扁平矢量
- 视觉：纯色块、几何形、无渐变、粗轮廓或无色线、现代移动端。
- 生成：`flat vector`、`geometric shapes`、`no gradients`、`bold silhouette`。
- code-draw：最适合的方向，直接画几何路径；色板锁定量化后几乎无损。
- 常见错误：偷偷加渐变/纹理、描边粗细不一、阴影过软。

### 写实厚涂
- 视觉：厚笔触、三点光、材质细节、电影感。
- 生成：`realistic painterly`、`thick brush strokes`、`AAA concept art`、`dramatic lighting`。
- code-draw：不适合；只建议生图或 prompt 包。
- 常见错误：卡通比例、塑料质感、细节糊。

## Style Card 字段

```json
{
  "name": "赛博像素",
  "keywords": ["16-bit pixel art", "neon rim light", "dark navy background"],
  "palette": ["#0B1020", "#1B2A4A", "#F2F5FF", "#29E0FF", "#FF4D8D"],
  "line": "1px dark outline, no anti-aliasing",
  "lighting": "top-left key light, hard shadow",
  "material": "matte surface with emissive accents",
  "referenceImages": ["refs/hero.png"],
  "avoid": ["3d render", "blurry", "photo texture", "text", "watermark"],
  "pixelGrid": 32,
  "paletteLock": true,
  "background": "transparent"
}
```

| 字段 | 作用 | 写法 |
|---|---|---|
| `name` | 风格名，出现在报告和联系表 | 中文短名 |
| `keywords` | 核心风格词，注入每次生图 prompt | 5~8 个英文短语，从大到小（画种 → 质感 → 氛围） |
| `palette` | 色板，后处理量化与校验的基准 | 6~16 个十六进制色；按「暗 → 中 → 亮 → 强调色」排列 |
| `line` | 描边规则 | 写清粗细、颜色倾向、是否抗锯齿 |
| `lighting` | 光照规则 | 写清主光方向、阴影硬度、辅助光 |
| `material` | 材质规则 | 写清表面质感、反光、磨损 |
| `referenceImages` | 参考图，相对项目根目录 | 1~4 张；没有就留空 |
| `avoid` | 负向词 | 至少 4 项；把最容易跑偏的东西写进去 |
| `pixelGrid` | 像素网格大小；0 表示非像素风 | 16 / 32 / 64 |
| `paletteLock` | 是否把成品量化到色板 | 像素风、扁平风建议 true |
| `background` | 默认背景 | `transparent` 或 `opaque` |

## 自定义风格流程

1. 从 `library/styles/` 复制最接近的一份到项目根目录，改名 `style.json`。
2. 先改 `palette`：把用户给的主色、辅助色、强调色按明暗排好。没有色板时从参考图提取。
3. 改 `keywords / line / lighting / material`：每个字段一句话，避免堆砌形容词。
4. 改 `avoid`：把「不想要的东西」写具体，例如 `text, watermark, blurry, 3d render, photo texture, soft gradient`。
5. 设定 `pixelGrid` 与 `paletteLock`：像素风网格对齐，扁平风锁色板；写实/手绘不锁。
6. 出 2~4 张锚点样图，检查色板是否够用、描边是否统一、光照方向是否一致。
7. 用户拍板后，在 `设计说明.md` 里记录最终字段和锚点 id。

## 一致性策略

1. **同一个 style block 注入每一次生成**：`plan.py --prompts` 会自动编译；手工写 prompt 时也要整段复制。
2. **身份锚点**：角色先做第一帧，后续帧以它为参考图（生图工具支持时）；不支持时把服装、发型、配色、身高、头身比逐条写进每帧 prompt。
3. **代码绘制共用色板**：`codegen/src/` 里的颜色必须从 `style.json` 抄，不允许另造颜色；改色板时全局替换。
4. **后处理锁色**：`paletteLock: true` 时 `process.py` 会把所有颜色映射到最近色板色。
5. **校验兜底**：`check_assets.py` 报告主色距离、像素风半透明比例、颜色数；超阈值先查风格漂移。

## 风格漂移排查

| 现象 | 先查 |
|---|---|
| 一批图里有的偏亮、有的偏暗 | 色板是否覆盖了明暗阶；`lighting` 是否写清 |
| 描边有的粗有的细 | `line` 字段是否具体；code-draw 是否每张单独写了 stroke-width |
| 同一角色前后不像 | 是否用了身份锚点；每帧 prompt 是否缺服装/发型/比例描述 |
| 颜色总数暴涨 | `paletteLock` 是否打开；code-draw 是否用了色板外的颜色 |
| 像素风边缘发虚 | 是否用了 Lanczos；SVG 是否有半像素坐标；是否开了抗锯齿 |
| 风格像上一个项目 | 是否直接复制了旧 `style.json`；是否忘了改色板和关键词 |
