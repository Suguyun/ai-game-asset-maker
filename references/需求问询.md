# 需求问询

需求问询是唯一必须停下来的人工卡点。目标不是把问题全问一遍，而是**用最少的轮次拿到能开工的全部事实**：做什么、给谁看、什么风格、多大、怎么用。

## 提问节奏

建议分 3 轮，每轮 3~5 个问题，每轮都给推荐项：

1. **定基本盘**：游戏是什么、平台、视角、引擎、现有素材。
2. **定素材与风格**：素材类型与数量、风格方向（附 3~4 张样图）、透明底、帧数。
3. **定规格与交付**：单帧尺寸、倍数、命名、交付目录、审阅方式、版权边界。

用户一次性说清楚了就合并轮次；不要为了走流程重复提问。

## 必问维度与推荐默认值

| 维度 | 问法 | 推荐默认 | 备注 |
|---|---|---|---|
| 游戏与平台 | 游戏叫什么、什么玩法、发在手机 / PC / 小游戏？ | 按用户回答 | 决定分辨率、视角、风格取向 |
| 视角 | 俯视 / 横版 / 45° 等距 / 3/4 / 第一人称？ | 俯视 2D | 所有构图的前提，必须先定 |
| 引擎 | Godot / Unity / Cocos / 自研？ | 通用 PNG | 决定九宫格、图集、导入设置 |
| 素材类型 | 角色 / 图标 / 背景 / 地形 / UI / 特效，各要多少？ | 先做验证批次 | 见「首批验证批次」 |
| 用途 | 主角 / 敌人 / 背包图标 / 技能 / 主菜单 / 关卡背景？ | 按用户回答 | 决定留白、可读尺寸 |
| 单帧尺寸 | 图标 128/256/512？角色 256/512？tile 32/64？ | 图标 256，角色 512，tile 64 | 可以按类型分别覆盖 |
| 倍数 | 需要 1x/2x/4x 吗？ | 图标 1x+2x，其余 1x | 见 `尺寸与图集.md` |
| 透明底 | 需要透明 PNG 吗？ | 角色/图标/UI/特效要；背景不要 | tile 可带透明细节 |
| 帧数与动作 | 待机 / 行走 / 攻击，各几帧？ | 待机 4 帧、行走 6 帧、攻击 4 帧 | 帧数越多成本越高 |
| 精灵表 | 要单帧还是精灵表，还是都要？ | 都要 | 脚本自动生成 |
| 风格 | 见「风格方向」 | 给 3~4 个方向让用户选 | 必须可视化 |
| 参考图 | 有没有角色设定、旧素材、色板、竞品参考？ | 有就一定要 | 版权边界先确认 |
| 命名 | 现有资源怎么命名？ | `<type>_<id>_<frame>@<scale>x.png` | 跟现有工程一致优先 |
| 交付 | 只要素材包，还是直接同步进工程？ | 先出素材包 | 不擅自覆盖工程 |
| 审阅 | 看联系表还是逐张看？ | 联系表 + 重点帧逐张 | 见 `校验清单.md` |
| 版权 | 是否有 IP 授权？能不能参考现成 IP？ | 只做原创 | 拒绝复制受保护 IP |
| 首批 | 先做几张验证风格，还是全量？ | 1 角色 + 3 图标 + 1 tile | 大单必须分批 |

## 风格方向

- 从 `library/styles/` 挑 2~3 个接近的方向，再自创 1 个「意想不到」的方向（Q 版、手绘、像素、极简、暗黑等）。
- 每个方向出一张**同题材样图**（同一个角色或同一个图标），不要用不同题材比较，否则用户会混淆「风格」和「内容」。
- 有生图能力就用生图；没有就用 `code-draw` 写 SVG 示意，或用几何色块画风格板。
- 样图拼成一张联系表，标注方向名和关键特征（描边、色板、光照、材质）。
- 推荐项放第一位，说明理由：例如「像素冒险：和你说的 16-bit 地牢最匹配，tile 64 也容易对齐」。

## 首批验证批次

用户一次要 10 张以上时，建议：

1. 先做 1 个最有代表性的角色（或 1 个核心图标，图标类游戏）。
2. 再做 1 个基础图标 + 1 个 tile。
3. 拼联系表让用户拍板风格、尺寸、透明边缘、留白。
4. 拍板后再全量生成。

把「首批结果」写进 `需求确认.md`，避免后面反复返工。

## 常见应答与暗坑

- **用户说「你决定」**：仍然要把风格样图给他看一次，但可以合并到最终确认里，不必单独一轮。
- **用户只给参考图、不给文字**：先从参考图提取色板、描边、光照、材质，写成 Style Card，再让用户确认字段，而不是口头说「照这个做」。
- **用户要「和某某游戏一样」**：拆成可执行的风格特征（像素密度、色板、描边、光照），不要复制具体角色和 IP。
- **用户说不清尺寸**：按用途给推荐值（背包图标 256、技能图标 128、角色 512、tile 64），并说明「先做一版，进引擎看效果再调」。
- **用户要很多帧**：先确认引擎动画帧率、每帧时长、循环方式；没有明确要求时按 8~12 FPS 设计。
- **用户要写实角色但工具没有生图能力**：先说明 code-draw 的表现边界，建议用 prompt 包模式或由用户提供参考图/生图结果，不要硬画一个低质替身。
