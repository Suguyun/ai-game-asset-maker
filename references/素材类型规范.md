# 素材类型规范

每种素材的构图目标不同。先确认它在游戏里怎么用，再决定留白、视角、帧数和透明处理。

## 通用规则

- **视角统一**：同一套素材必须共用同一个视角和透视（俯视、横版、45° 等距、3/4）。混用视角比画得不好看更致命。
- **可读尺寸优先**：图标缩到游戏里的实际显示尺寸（常见 32~64px）仍然能认出是什么。
- **安全边距**：对象类素材四周至少留 `padding`，不要把主体顶到画布边缘；引擎缩放/描边会吃掉边缘。
- **光源统一**：所有素材的主光方向一致（默认左上），阴影方向一致。
- **透明底**：角色、图标、UI、特效默认透明；背景不透明；tile 可有透明细节，但主体纹理要铺满。
- **不要文字**：游戏素材默认不带文字，文字由引擎渲染；确实要字时单独列一项 UI 素材并说明字体。

## 1. character：角色 / 怪物

- **用途**：主角、NPC、敌人、Boss 的立绘或动作帧。
- **构图**：单个角色全身，正面或 3/4 视角，脚底贴齐画面底部，居中；四肢轮廓清晰，不要和身体糊在一起。
- **尺寸**：512×512（默认），像素风可用 64/128/256 的整数倍。
- **帧**：待机 4~6、行走 6~8、攻击 4~6、受击 1~2、死亡 4~6。帧数先问用户，不要擅自加。
- **一致性**：同一角色的所有帧必须同身高、同头身比、同服装细节、同配色；脚底基线一致（`check_assets.py` 会查）。
- **透明**：必须。
- **常见错误**：每帧比例漂移；武器换手；披风长度变化；脚底基线不齐；正面/侧面混用。
- **验收**：把各帧并排看，像同一个角色；缩到 64px 仍能看出动作。

## 2. sprite：精灵表专用角色

- **用途**：按固定单元格切分的动作帧，直接进引擎动画或图集。
- **构图**：每帧角色在单元格内居中，脚底基线一致；动作幅度不要超出单元格。
- **尺寸**：`cell` 32/48/64/96/128；列数按动作帧数定。
- **帧**：由 `frames` 顺序决定，图集 JSON 里记录每帧坐标。
- **透明**：必须。
- **常见错误**：帧和单元格尺寸不一致；动作超出格子被裁；列数和帧数不匹配；图集 JSON 与图片不同步。
- **验收**：`atlas/<id>.json` 的帧数、单元格、坐标与实际图片一致；逐帧播放无跳动。

## 3. icon：道具 / 技能图标

- **用途**：背包、商店、技能栏、掉落物、成就。
- **构图**：单个主体，居中，剪影清晰；主体包围盒较长边占画布 70%~95%，四周留均匀空白；不要场景背景。
- **尺寸**：256×256（默认），小图标可 128，商店大图 512；导出 1x/2x。
- **帧**：通常单帧；技能冷却/发光可用 2~4 帧。
- **透明**：必须。
- **常见错误**：主体太小；主体贴边；背景没抠干净；白边/黑边；同一套图标描边粗细不一；光源方向乱。
- **验收**：缩到 32px 仍能认出；同套图标并排看像一套；透明边缘干净。

## 4. background：场景背景

- **用途**：主菜单、关卡背景、过场、弹窗底图。
- **构图**：完整场景，无 UI、无文字、无水印；主体信息避开画面中央，方便叠加角色和界面；注意视差分层需求（远景/中景/近景）时，要拆成多张并说明层次。
- **尺寸**：1920×1080（默认）；竖屏 1080×1920；移动端可按 1280×720 设计再放大。
- **帧**：通常单帧；循环背景可做 2~4 帧或交给引擎滚动。
- **透明**：不透明。
- **常见错误**：带文字/水印；中央太满导致角色看不清；明暗对比过强抢主体；分辨率不足。
- **验收**：叠上角色和 UI 后主体仍清晰；无文字水印；边缘可裁切。

## 5. tile：可平铺地形

- **用途**：地表、墙面、水面、装饰地砖。
- **构图**：正视角或与游戏视角一致；光照均匀；不要有明显中心构图或方向性阴影；四边可首尾相接。
- **尺寸**：32×32 / 64×64（默认 64）；导出 1x/2x。
- **帧**：通常单帧；水面/岩浆可 2~4 帧循环。
- **透明**：可有透明细节，但主体纹理要铺满；不透明 tile 也合法。
- **常见错误**：接缝明显；四边光照不一致；中间有强焦点；边缘有半透明杂色。
- **验收**：3×3 平铺预览无可见缝；`check_assets.py` 接缝误差 ≤ 0.08；不透明像素占比 ≥ 30%。
- **修补**：接缝超标时优先重生成；其次用 offset-seam（把图平移半格后修补接缝，再平移回来），见 `后处理.md`。

## 6. ui：界面元素

- **用途**：按钮、面板、边框、血条、图标框、光标。
- **构图**：可九宫格拉伸；四边设计一致，四角细节完整；中间区域可平铺；默认不带文字。
- **尺寸**：按钮/面板按实际显示尺寸设计，常用 512×128、256×64；九宫格边距写进 `nineSlice`。
- **帧**：1 帧（常态）；按下/悬停/禁用状态各单独一项，不要塞进同一张图。
- **透明**：通常透明（面板中间可透明或半透明）。
- **常见错误**：四角细节不对称；九宫格边距把角切坏；中间有不可平铺的图案；边缘 1px 线在高 DPI 下发虚。
- **验收**：拉到 2~3 倍尺寸，四角不变形、边线不糊；九宫格边距合法；透明区域干净。

## 7. vfx：特效序列帧

- **用途**：打击、爆炸、拾取、治疗、升级、传送。
- **构图**：单个特效主体，居中；各帧尺寸、锚点、配色一致；按时间顺序排列。
- **尺寸**：`cell` 64/128/256；列数按帧数定。
- **帧**：4~12 帧；循环特效要说明首尾可循环。
- **透明**：必须。
- **常见错误**：帧与帧之间位置漂移；颜色突变；首尾不循环；特效超出单元格被裁。
- **验收**：逐帧播放流畅；锚点稳定；图集坐标正确；缩到游戏实际尺寸仍有冲击力。

## 类型与生成模式建议

| 类型 | 首选模式 | 理由 |
|---|---|---|
| character / sprite（写实、手绘、厚涂） | ai-image | 代码绘制难以表现细节和材质 |
| character / sprite（像素、扁平） | code-draw | 像素级精确、可复现 |
| icon（几何、UI 风、像素） | code-draw | 主体简单、对齐和色板可控 |
| icon（写实、复杂材质） | ai-image | 细节和光影更自然 |
| background | ai-image | 场景复杂度高；简单几何背景可 code-draw |
| tile（平铺纹理） | code-draw 或 ai-image | 几何/像素 tile 代码更稳；自然纹理用生图 |
| ui | code-draw | 九宫格、圆角、边线需要像素级控制 |
| vfx（几何、像素） | code-draw | 帧间一致性要求高 |
| vfx（烟雾、火焰、写实） | ai-image | 自然形态难用代码画 |
